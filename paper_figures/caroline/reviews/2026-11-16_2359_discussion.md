```latex
\section{Discussion And Limitations}\label{sec:discussion}
% GOAL: show that a hit under the directives is a leak the defense claims to prevent, because the directives change only prediction and resolution timing, which an attacker controls too.
\noindent\textbf{Soundness of the harness.} The harness changes only which way each annotated branch is predicted and how long its resolution is held or delayed (\S\ref{sec:speculation-directives}). Its hooks never touch the defense's state or code; besides these overrides and print-only logging, their one effect is to wake the core when a hold ends, as gem5 does for a late memory response. The directives thus produce only a misprediction and a late branch resolution, both of which a Spectre attacker can cause by training the predictors and evicting the data a branch condition depends on~\cite{spectre}. No defense we test changes how the predictor predicts (STT delays only its updates~\cite[\S 6.4.1]{yu2019stt}). A long hold can make a leak easier to trigger than natural timing would, but AMuLeT's fuzzer, which uses no directives, also triggers UV5 (\S\ref{sec:uv5-speclfb-shadow-jmp}).
% support: pipeline.tex:114 (directives, timing grid), pipeline.tex:110 (neither touches the defense's logic), results.tex:70 (AMuLeT's fuzzer triggers UV5 in 47 of 248 violations); STT §6.4.1 (predictors updated only with untainted resolution results)

% GOAL: disclose the one non-default core parameter behind a reported bug (UV6) and say why UV6 still counts as a bug.
\noindent\textbf{A non-default pipeline delay.} UV6 (\S\ref{sec:bug-race}) needs a squash that takes longer than gem5's default of one cycle to reach the issue stage: it appears with \texttt{commitToIEWDelay} at 3 and 4 on STT and at 4 on SPT, and in no test we ran at the default. This stock gem5 parameter is set once per run and changes no defense logic, but it changes the simulated microarchitecture, so we report UV6 with it. We count UV6 as a bug because STT's paper delays a transient transmitter ``until the mispredicted explicit branch B squashes''~\cite[\S 6.4.2]{yu2019stt}, as our violation window does (\S\ref{sec:transmission-requirement}), whereas both implementations release the transmitter at resolution.
% support: results.tex:75 (STT at 3; SPT 1,674 of 2,000 at 4 and 0 of 2,000 at 1; both release on resolution), intro.tex:320 ("3 or 4 cycles"), pipeline.tex:138-140 (window ends at the squash; same STT quote)

% GOAL: state exactly what a hit claims, and name the one class of hits we do not count as a bug, with the reason.
\noindent\textbf{What we count.} We check each simulated Spectre defense only against the security guarantee its own paper states, with no adversary model: a hit is a run in which the target transmitter meets the defense's transmission criterion inside the violation window, even if no particular attacker could measure it. We do not count one class of hits. ReCon's implementation of STT never marks a floating-point load speculative, so its result is never tainted (\texttt{decode.cc:691--692}); this accounts for about 70\% of the vector version's hits on ReCon's implementation of STT. The skip is a side effect of disabled code that would treat floating-point instructions as possible exceptions, a source of speculation that ReCon's evaluation leaves out~\cite[\S 6.1]{recon}, so we cannot tell whether it is intended.
% support: results.tex:32,35 (scope; AMuLeT's four out-of-scope reports), pipeline.tex:110 (hit, leak, bug), pipeline.tex:138 (window); decode.cc:685-695 and the 70% (E2w 72%, E2w-stl 70%): simspect wiki/findings/bug/RECON_FP_LOADS.md; ReCon §6.1 "We do not consider speculation triggered by load instructions and instructions that can raise an exception"

% GOAL: state the trust base (hand-written specifications) and its one known gap.
\noindent\textbf{Specifications.} We write each specification by hand from its defense's paper (\S\ref{formalmodel}), so a translation error can make us miss a bug or report a spurious hit. One gap is known: SPT's backward untaint rules depend on each instruction's operation~\cite[\S 6.6]{spt}, which our ALU op does not name, so SPT's specification untaints less than SPT does and can forbid executions that SPT permits.
% support: model.tex:5 ("written by hand from the defense's paper"); SPT §6.6 "Backward (Input) Untainting ... For register MOV instructions ... For invertible arithmetic instructions (e.g., ADD)"

% GOAL: state exactly which part of the suite is exhaustive and up to what bound, and what is sampled or switched off.
\noindent\textbf{Completeness.} Only Stage~1a is exhaustive, and only up to six instructions. For every specification except SPT's, it reaches UNSAT and no leakage backbone has more than three instructions (\S\ref{sec:test-generation-alloy}); SPT's enumeration stops at a cap of 200{,}000 four-instruction backbones, so SPT's suite is not exhaustive even within the bound. We have not shown that no backbone has seven or more instructions. Stage~1b, Stage~2, and the harness sample extended execution graphs, instruction choices, and timing settings, respectively, and Pass~4, which can make a transmitter's operand depend on two independent speculative sources (\S\ref{sec:conc-interleave}), is off in our evaluation.
% support: pipeline.tex:36 (UNSAT except SPT; no backbone over three), pipeline.tex:61 (Stage 1b capped, seeded random order), pipeline.tex:80 (Pass 2 uniform at random), pipeline.tex:114 (each test draws one setting), pipeline.tex:99 (Pass 4 off); cap: simspect wiki/state/EVAL_MANIFEST.md:121, :139

% GOAL: list the executions and instructions the synthesizer never builds, with a reason where we have one.
\noindent\textbf{Coverage.} Stage~2 builds every unresolved branch as mispredicted (Table~\ref{tab:instrtable}, row~1), never as correctly predicted: a transmitter whose only older unresolved branch is correctly predicted is sequential, so it transmits only data that the committed execution also transmits. Under store bypass, it builds only a load that aliases the older store but is predicted not to (\S\ref{sec:speculation-primitive-instrumentation}). The vocabulary leaves out indirect jumps and calls, returns, atomic read-modify-writes such as \texttt{xchg}, faulting instructions as a speculation primitive, and a second core, e.g., for an InvisiSpec request that downgrades another core's copy of a line.
% support: tab:instrtable row 1 (forced to mispredict), background.tex:9, :12 (store bypass = predicted not to alias; sequential = bound to commit), pipeline.tex:87 (only this direction), results.tex:70 (direct jmp and call are in the vocabulary)

% GOAL: account for each previously known bug that SimSpect does not find (Protean's two), with the reason each is missed.
\noindent\textbf{Known bugs we miss.} \toolname{} misses both bugs that Protean reports in STT and SPT. Protean's extension of AMuLeT found a pending-squash timing leak in their shared branch-resolution logic~\cite[\S VII-B4b]{protean}: an older tainted branch that mispredicts blocks the squash of a younger untainted branch that mispredicts in the same cycle, so whether the younger branch squashes reveals the tainted branch's condition. Our extended execution graphs never contain the younger branch, because Stage~1b adds only instructions that connect to the transmitter through dataflow or a shared memory word (\S\ref{sec:stage1b}). Protean's authors found that, after a fault reaches commit, SPT untaints the L1D bytes that transient loads outside the ROB access~\cite[\S VII-B4c]{protean}; our tests are not built to fault (\S\ref{sec:conc-interleave}). Our STT and SPT builds and AMuLeT's STT build predate the fixes~\cite{nickscommittoSTT,mosier2025sptpr4,mosier2025sptpr6}.
% support: Protean §VII-B4b ("an older tainted/protected branch can conditionally block a younger untainted/unprotected branch from initiating a squash depending on whether the former was mispredicted"), §VII-B4c ("We manually discover a corner-case implementation bug in SPT that AMuLeT* misses"); pipeline.tex:61 (Stage 1b connection rule); pipeline.tex:101 (no access faults); intro.tex:75 (seven known bugs)

% GOAL: say what porting SimSpect to RTL, silicon, or a new speculation primitive requires (future work).
\noindent\textbf{Generality.} RTL simulation exposes the predictor and pipeline signals that the harness forces and the Inspector reads; on silicon, the directives would have to come from predictor training and eviction, and a hit would have to be measured through a side channel. Each further speculation primitive, such as value prediction or the microcode branch mispredictions that $\mu$Spectre exploits~\cite{mosier2025uspectre}, needs its own execution-contract entry and harness directive.
% support: future work (design argument); store bypass already has both (pipeline.tex:87, :114)
```
