```
\subsection{Harness: Directives And Cache State}\label{sec:speculation-directives}
The harness's hooks sit in gem5's branch predictor and out-of-order pipeline. \emph{Speculation directives} come from the test's annotation (Table~\ref{tab:instrtable}): at each annotated branch, the harness overrides the predictor, forcing an unresolved branch to mispredict and a resolved one to predict correctly. \emph{Timing directives}, the target execution's resolution times, come from the run configuration: the harness holds each unresolved branch so that it is still unresolved when the transmitter acts, and delays each resolved branch, by cycle counts drawn at random (Table~\ref{tab:instrtable}, rows~1--2), so that tests vary when resolved branches resolve. \subsection{Inspector: Transmission Criteria}\label{sec:transmission-requirement}
```
```
The Inspector decides from the trace whether a transmission occurred inside the \emph{violation window}: after the annotated last committed instruction (lc) retires, before the first uncommitted instruction (fnc) retires, and while every branch the graph marks unresolved is still unresolved, i.e., before its squash lands (Fig.~\ref{fig:checkerwindow}). Inside this window the run matches the graph's commit boundary and unresolved branches, so a transmission there is one the leakage predicate forbids. A run in which a forced prediction or hold did not take effect is invalid, never a hit. Print-only hooks log the events gem5 does not print, such as a branch's prediction and resolution.

What counts as a transmission is the transmission criterion of the defense's leakage contract (\S~\ref{sec:leakage-predicate}, Table~\ref{tab:specs}). The Inspector times a load at the tick it executes, so a load that executes inside the window and obtains its data transmits even if it is squashed later; it times a branch at its redirect and a store at its completion. For the footprint defenses it checks every transient load younger than lc, not only the transmitter, and on CleanupSpec it also counts a cleanup that removes a line an older committed access used. On InvisiSpec we run its Futuristic mode, in which a load's change counts if it precedes the load's visibility point, inside the window or not~\cite[\S V-A1]{yan2018invisispec}. A \emph{violation} is an execution graph that violates the defense's leakage predicate (\S~\ref{sec:leakage-predicate}); a \emph{hit} is a test whose run meets the transmission criterion; a \emph{leak} is a hit that we confirm, on its trace, is not a harness or Inspector artifact; and a \emph{bug} is a leak that the defense's paper claims to prevent.
```
