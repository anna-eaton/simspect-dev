## Proposed paragraph (LaTeX)

```latex
\paragraph{Validating speculative-execution defenses.}
Most leakage testing is randomized. Revizor~\cite{revizor} and its follow-ups~\cite{oleksenko2023hideseekspectresefficient,hofmann2023speculationatfault} test commercial CPUs against speculation contracts, and AMuLeT~\cite{amulet} brings this relational testing to gem5 prototypes of secure-speculation defenses. Pre-silicon fuzzers search RTL for transient-execution bugs, using differential execution~\cite{hur2022specdoctor,xu2025dejavuzz}, gadget-driven simulation~\cite{ghaniyoun2021introspectre}, information-flow tracking~\cite{rostami2024specure,defaveritron2025phantomtrails}, or contract-guided coverage~\cite{geier2025coverage}; TEESec~\cite{ghaniyoun2023teesec} applies similar pre-silicon testing to enclave isolation. SpecCheck~\cite{mckevitt2023speccheck}, the closest gem5-based tool, monitors simulation for a generic transient-attack pattern. Scam-V~\cite{nemati2020scamv} generates tests that validate an abstract side-channel model against hardware. Formal methods instead prove secure speculation for RTL designs~\cite{fadiheh2019upec,contractshadow,dong2026interplay}. \toolname{} differs from the testing tools in two ways. It checks each simulated defense against that defense's own guarantee, not a generic attack or a sequential contract. And it enumerates only programs that provably contain a leak shape the defense must block, rather than sampling programs at random.
```
