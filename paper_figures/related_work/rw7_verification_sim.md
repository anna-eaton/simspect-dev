## Proposed paragraph (~150 words; for Anna to paste, not inserted)

```latex
\para{Formal verification of secure speculation}
Formal methods verify secure speculation at the register-transfer level. UPEC~\cite{fadiheh2019upec} and Contract Shadow Logic~\cite{contractshadow} model-check processor RTL for transient leaks, LeaVe~\cite{leave} verifies open-source cores against leakage contracts, and Compass~\cite{yang2026compass} chooses the cheapest taint scheme that still proves security, building on hardware information-flow tracking~\cite{tiwari2009glift,hu2021hwift}. ConjunCT and H-Houdini~\cite{dinesh2024conjunct,dinesh2025hhoudini} prove which instructions are safe, scaling to the BOOM out-of-order core. These tools need RTL, but most proposed defenses exist only as gem5 prototypes~\cite{gem5}, which \toolname{} tests directly. Simulator-based security evaluation is sensitive to configuration: whether a Spectre attack even reproduces in gem5 depends on the simulated predictor and setup~\cite{ayoub2021gem5spectre}. \toolname{} removes that dependence by forcing each annotated prediction and stall through its hooks, and it judges a prototype only by its own stated guarantee, not by performance fidelity to silicon~\cite{nowatzki2015harmful}.
```

Notes on the paragraph: (1) "most proposed defenses exist only as gem5 prototypes" is a framing claim; it holds for the six defenses tested (all gem5) but is not a measured statistic, so soften to "many" if no source is added. (2) H-Houdini's BOOM result used expert annotations (paper excerpt), so "scaling to BOOM" is accurate only with that caveat. (3) The paragraph overlaps related.tex part (1), which already plans UPEC and Contract Shadow Logic; merge rather than add a second paragraph.
