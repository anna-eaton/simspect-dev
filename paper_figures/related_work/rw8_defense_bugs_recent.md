## Overlaps with SimSpect findings (read first)

- **ReCon multi-source leak (overlaps the getOldestTaint finding).** Kvalsvik and Själander's IEEE DataPort abstract (June 2025, DOI 10.21227/dkjt-k008) says: "We show that ReCon leaks potential secrets in cases where an instruction has multiple secret sources." They also say the ReCon+STT combination undermines STT's guarantee, and they propose a fix called ReConnaissance. This may pre-empt SimSpect's "getOldestTaint keeps only the oldest source" finding at the design level. I could not find the paper's title, venue or text (TODO). Anna must decide how to frame UV novelty.
- **SPT partial-register writes (adjacent to SPT backward untaint through partial writes).** Mosier's FPSG-UIUC/SPT PR #5 (merged 2025-12-14) adds an unconditional untaint of the upper 32 bits of 32-bit destination writes. That is a precision change, not a security fix, but it touches the same partial-write taint code. Check whether our SPT build includes PRs #4, #5 and #6.
- **SPT pending-fault untaint bug (PR #6, Protean §VII-B4c).** Transient loads that bypass ROB insertion after a fault keep untainted outputs, so SPT's shadow-L1 logic untaints secret memory. This is a different mechanism from ours, but it is another SPT untaint-implementation bug.
- **STT/SPT pending-squash bug.** Mosier found it with AMuLeT* (Protean §VII-B4b) and fixed it in STT PR #10 and SPT PR #4. It is already in the paper's Table as `nickscommittoSTT`. Protean also found that division micro-ops are gem5 transmitters.
- **STT/DOLMA bypass via CMOV + REP (USENIX Sec 2026).** Cheng et al. bypass STT and DOLMA in gem5 through RS contention, using CMOV-selected REP-string µop expansion. This is a design-level blind spot, not our xmm taint drop, but it is the newest gem5 STT break.
- I found no prior report of: STT taint dropped through xmm registers, ReCon STL-forward skipping the taint check, ReCon SSE loads never marked speculative, NDA store-forward skipping delay, DoM line-crossing bypass, SpecLFB direct-jmp shadow clear, or CleanupSpec squashed RMW E->M. The search was partial, so these are TODO and not yet confirmed novel.

\paragraph{Prior defense flaws.} Hardware Spectre defenses have repeatedly been broken after publication, both in design and in implementation. Design-level attacks include speculative interference against invisible speculation~\cite{behnia2021interference,aimoniotis2021robcontention}, unXpec against undo-based CleanupSpec~\cite{li2022unxpec}, DOLMA's speculative-store and memory-ordering channels in STT~\cite{loughlin2021dolma}, and, most recently, reservation-station contention through CMOV-selected \texttt{REP} string micro-ops that bypasses STT and DOLMA in gem5~\cite{cheng2026contention}. Implementation bugs in the gem5 prototypes have surfaced only recently: AMuLeT~\cite{amulet} reports nine bugs across four defenses, and Protean's extended fuzzer and manual audit found a secret-dependent pending-squash signal in STT and SPT and an SPT untaint bug on pending faults, since fixed upstream~\cite{protean,mosier2025sttpr10,mosier2025sptpr6}. Kvalsvik and Sj\"alander report that ReCon leaks when an instruction has multiple secret sources~\cite{kvalsvik2025reconnaissance}. \toolname{} complements these case-by-case findings by deriving tests from each defense's own model; its new bugs (Sec.~\ref{sec:results}) are not covered by any prior report we found.
